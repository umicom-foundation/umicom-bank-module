User guide: inspect a training account workflow

Start with simulated customer and account data. A banking interface should make the selected account, currency, available balance and processing state clear. A staged command is not a settled payment, and an approval request is not proof that money moved.

  1. Open the banking workstation and identify the configured environment.
  2. Inspect the available account and transaction views; an empty provider should explain that state.
  3. Follow a training instruction through validation and the available approval stages.
  4. Read its reported state and associated evidence. Do not repeat an instruction just because a display has not refreshed.
  5. Review persisted records and reconciliation when those services are configured, rather than treating a changed widget as a ledger posting.

The financial engines belong to Framework. Provider connection, authorisation, durable ledger processing and operational recovery must be independently completed before any real-money use. This guide does not present the development workstation as a regulated banking service.

Support and contribution

When reporting a problem, include the application revision, operating system, exact action and error output. Remove credentials, private account information and personal file content. Use the repository issue tracker for a reproducible defect and the contributor guide for documentation improvements.
