Umicom Bank user guide: reviewed local operations

Banking operations is a local simulation backed by Framework services. It supports practice records, approvals, journals and reports. It has no real payment or card network. The Test maker, Test checker and Test operator selections are simulation roles, not authenticated identities.

Choose and open a banking database

A database is the file containing your practice records. Choose where this file lives before opening the workspace.

  1. Launch Umicom Bank. In the banking launcher, choose Browse existing... to reuse a simulation database, or Choose new location... to select a filename in an existing folder.
  2. Check the complete filename in the location field. You can type an absolute local path there. An absolute path starts at the drive or filesystem root.
  3. Choose Banking operations. A successful open shows the selected path and the simulation banner. A failed open leaves the launcher available: correct the filename, folder or permissions and retry.
  4. Inspect the counts and current revision. A revision changes after an accepted command is committed.

Choosing a path does not create a database. Opening it may create the selected database file. This launcher does not create parent folders, move old databases, or remember the choice between application launches. Use your file manager to create a practice folder first.

While the workspace is open, the Banking operations button returns to that same window. To use a different database, close the workspace, choose another filename and open again. Existing application-data databases can still be selected explicitly; they are not moved automatically.

The bounded evaluation store has catalogue and accepted-command limits. Use fictional data and retain the database when investigating a problem.

Create one practice customer

  1. Select the create-customer action and Test maker.
  2. Choose New request. The request ID identifies this operation; keep it distinct from the customer’s Entity ID.
  3. Enter a new Entity ID, such as practice-customer, a fictional name and a business date in YYYY-MM-DD form.
  4. Choose Review command. Inspect the prediction in the Command review page. A review must not add a customer or change the ledger.
  5. Choose Submit command only when the reviewed details are correct.
  6. Inspect Customers, Audit and the revision. The accepted command should appear once.

Changing a field after review invalidates that review. Review the edited form again before submitting. Repeatedly clicking Submit must not create duplicate customers or financial effects.

Use accounts and reports

Each action displays the fields and simulation role it requires. Follow those hints for accounts, transfers, beneficiaries, approvals and card holds. Values labelled Integer minor units use the currency’s smallest unit: with GBP and scale 2, 125 means £1.25. Do not enter 1.25 into an integer field.

  1. Enter the relevant account ID in the statement field and choose Show statement.
  2. For a bounded report, use Statement report and choose the first and last revisions.
  3. Use Reload committed data to inspect newer commits, then request the report again.
  4. Read the export label carefully: the displayed text snapshot and CSV requested from current fields have different sources.

A report is a copied observation. It does not approve a payment, reserve funds or perform a transfer.
